# AI 使用与验证记录

## AI 在开发中的作用

| 环节 | AI 的作用 | 人工应执行的验证 |
|---|---|---|
| 产品拆解 | 将题目约束拆成数据、计算、证据、解释和降级层 | 对照原题逐条检查交付物 |
| 代码初稿 | 生成 Provider、指标、证据和页面结构 | 运行测试，检查边界条件 |
| 指标实现 | 生成同比、比率、分位、波动率和回撤实现 | 使用简单样例手算核对 |
| 诊断输出 | 把证据分为正面、负面、矛盾和未知 | 检查每条结论是否引用有效证据 ID |
| 文档 | 生成启动、数据契约和边界说明 | 按实际部署环境修订 |

## 产品中的 AI 分工

LLM 接收用户问题和已经计算完成的证据对象，返回结构化解释。它不能直接读取数据库、计算关键数字或补充输入中不存在的事实。

调用后执行以下校验：

1. 四类发现必须是数组；
2. 每条发现必须引用至少一个证据 ID；
3. 引用 ID 必须存在于本次输入；
4. 解析或校验失败时回退到确定性归纳；
5. 页面明确显示本次使用 LLM 还是确定性降级。

## 已识别的 AI 风险

- 添加证据中不存在的数字；
- 混淆事实和分析推断；
- 把缺失数据解释为正常；
- 给出确定性涨跌预测或买卖建议；
- 引用不存在的证据；
- 在接口失败后仍生成看似完整的结论。
